# Workspace format

Sonata initializes `inbox`, `tasks`, `notes`, `ideas`, `bookmarks`, `archive`, `attachments`, `.trash`, and `.sonata`. `.sonata/config.json` is workspace configuration and `.sonata/index.db` is regenerable; the `folders` key there is reserved and not yet honored, so renaming a folder in it has no effect. Each document type carries only the metadata that type supports — a bookmark has a `bookmark.url` and no `status`, an idea has a `stage` (`spark`, `developing` or `parked`) instead of a status, and a note carries neither. Changing a document's type moves its file to the new type's folder and drops the frontmatter keys the new type does not support. A task's `reminder` is a local wall-clock instant written as either `2026-09-10` or `2026-09-10T15:30`; there is deliberately no timezone, so a reminder means that clock time wherever you are. A date with no time is delivered at 09:00 local. Sonata notifies once per reminder value, so editing a reminder re-arms it, and a reminder more than a day past its time is retired without a notification rather than firing a backlog at you. Documents use YAML frontmatter plus ordinary GFM Markdown. Unknown frontmatter keys survive Sonata edits.

Attachments are copied to `attachments/<document-id>/`. Sonata inserts ordinary workspace-relative Markdown references such as `![photo.png](attachments/<document-id>/photo.png)` (or a normal link for non-images), so notes remain readable outside the app. An image cover is stored as the optional `cover` frontmatter key pointing to that same relative attachment path.
